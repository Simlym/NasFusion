# 下载完成后的持久化整理与开机恢复

适用场景：NAS 夜间关机，第二天启动；应用升级重启；下载完成或整理期间进程异常退出。

## 恢复行为

- 下载进度达到 100% 时，在下载状态的同一事务写入 `workflow_events`。
- 业务唯一键为 `download_completed:organize:<workflow_token>`，旧数据使用下载 ID 作为后缀。新下载使用持久化 UUID，防止 SQLite 删除后复用 ID 时误判为旧任务。重复状态同步、重复事件或并发投递不会创建多个自动整理任务。
- 后台每 10 秒补偿尚未记录事件的已完成下载、投递事件并消费到期任务，恢复消费者最多同时执行 2 个任务。
- 整理任务创建和事件确认在同一事务提交。崩溃发生在提交前时回滚，发生在提交后时继续执行已经落库的任务。
- 开机保留所有 `pending` 任务。上次运行中的自动整理、下载状态同步重新入队，不增加失败重试次数。
- 旧版本标记为“系统重启，任务被中断”的上述安全任务也会恢复。其他运行中任务仍需检查外部执行结果后手动重试，避免重复提交下载等副作用。
- 历史完成下载优先关联已有的整理任务；保留已有成功、失败和取消结果，不绕过用户取消。
- 新建的持久化整理任务最多进行 6 次失败重试，按 60、120、240、480、960、1920 秒退避。耗尽后在任务中心显示失败；修复路径、挂载或识别问题后再手动发起整理。

## 文件恢复与边界

自动整理只处理当前下载任务关联的文件，不认领共享下载目录的其他种子。每个成功文件保存 `organized` 检查点，重试跳过目标仍然存在的已完成文件，不重复覆盖。

文件副作用之前在 `media_files.sub_status.auto_organize_checkpoint` 保存计划目标。硬链接使用文件身份验证；复制/reflink 在需要恢复时比较 SHA-256；移动在操作前保存 SHA-256，以便源文件已不存在时验证目标，因此移动模式会额外读取一次源文件。

底层文件操作和数据库并非同一事务。本实现不承诺任意断电下的文件系统 exactly-once：半截复制、无法验证的蓝光目录和无检查点的已有目标会保留现场并报错，需要人工核对，不会作为成功吞掉或自动覆盖。已完成主视频但附属字幕尚未完成的极端中断，应核对字幕；媒体服务器刷新通知和其他普通通知仍使用内存事件总线。

下载路径缺失、目标目录不可用、没有找到当前种子的文件、识别缺失或整理返回错误都不会再被记录为成功。目录存在性检查不能证明 NAS 的远程挂载已真正就绪；应保证系统先挂载存储再启动容器，尤其避免把未挂载的空目录当成媒体库。

恢复初始化沿用当前单后端进程部署模型。不要同时启动多个后端实例或多个 Uvicorn worker；跨进程启动恢复需要额外的 worker 租约机制。

## 部署与排查

新增迁移 `5bb170d6737e` 创建 `workflow_events` 表和索引，`ec7094f8e612` 增加下载任务的 `workflow_token`。应用启动时沿用现有自动迁移流程，也可执行 `alembic upgrade head`。升级前按常规备份数据库；本次开发验证使用临时数据库，没有迁移开发者现有数据。

开发阶段的历史迁移 `193dbdf95aa1`、`c7d8e9f0a1b2` 已直接修正为兼容 SQLite 的 batch 操作，并校验可能由 `create_all` 提前创建的 LLM 表和字段。SQLite 升级使用显式事务，后续步骤失败时回滚结构与版本记录；启动迁移失败会停止启动，避免继续使用不完整的结构。自动迁移使用当前 Python 解释器下的 Alembic。

SQLite 文件数据库改用独立会话连接，避免并发生产者与消费者共享 `StaticPool` 的同一连接、意外提交对方事务。内存数据库仍保留 `StaticPool`。

任务中心可以查看恢复后任务状态及逐文件日志。`workflow_events` 的 `attempts`、`next_attempt_at`、`last_error` 用于排查投递失败；`execution_id` 指向整理任务。投递凭据不能随任务历史一起删除，否则将失去长期业务去重。任务历史被清理时外键设为 NULL，事件仍保留为 delivered。

只补偿已有下载任务和执行记录，不会把关机期间错过的每一次 cron 触发全部补跑。

## 验证

`tests/unit/services/test_durable_workflow.py` 使用临时 SQLite 数据库和临时媒体文件，覆盖事务回滚、关闭会话后重放、重复/并发投递、启动恢复策略、原子认领、重试截止时间和文件检查点恢复。实际 NAS 断电与远程文件系统仍需部署后验证。
